## Overview & Valid States

The system defines exactly **9 valid client states** as constants in the API:

```typescript
const VALID_STATUSES = [
  'intake',                    // State 1
  'assessment_pending',        // State 2
  'ready_for_booking',         // State 3
  'booking_scheduled',         // State 4
  'payment_pending',           // State 5
  'active',                    // State 6
  'completed',                 // State 7
  'inactive',                  // State 8
  'booking_expired'            // State 9
] as const;
```

**Database Constraint:**
```sql
status VARCHAR(50) NOT NULL DEFAULT 'intake' CHECK (status IN (
  'intake',
  'assessment_pending',
  'ready_for_booking',
  'booking_scheduled',
  'payment_pending',
  'active',
  'completed',
  'inactive',
  'booking_expired'
))
```

No other status values are allowed. Any attempt to set a status outside this list will fail with a 400 error.

## State-by-State Breakdown

### 1. INTAKE

**Status Code:** `intake`  
**Initial State:** YES (all clients start here)  
**Dead End State:** NO  
**Entry Point:** Automatic (created via intake form submission)

#### Definition
The **INTAKE** state represents a newly registered client who has just submitted their intake form. The client record exists in the system but has not yet been clinically evaluated.

#### What This Means

- ✅ Client profile created with basic information
- ✅ Name, contact info, primary concern recorded
- ✅ Initial status history entry created
- ✅ Not yet scheduled for any sessions
- ✅ Therapist not assigned
- ✅ No bookings exist
- ❌ No sessions completed
- ❌ No payments processed
- ❌ Not ready for therapy yet

#### Who Assigns This State
- **System (Automatic):** When intake form submitted
- API endpoint: `POST /api/admin/clients/intake`
- Status automatically set to `'intake'`

#### Typical Duration
- **Minimum:** Minutes to hours (if clinician reviews immediately)
- **Maximum:** Days to weeks (pending clinic workload/assessment scheduling)
- **Typical:** 2-7 days

#### Clinician Actions at This State
1. **Review intake form data:**
   - Verify all information is complete
   - Assess primary concern
   - Check referral source
   - Review preferences

2. **Determine next steps:**
   - Option A: Additional info needed → Stay in `intake`
   - Option B: Ready for assessment → Change to `assessment_pending`
   - Option C: Not suitable/decline → Change to `inactive`

3. **Collect supplemental information (if needed):**
   - Full medical history
   - Medications
   - Previous therapy experience
   - Insurance details (if applicable)

#### Client-Facing Communication
- Client may receive email: "Thank you for your intake submission. We'll review your information and contact you within [X] hours/days."
- Client website may show: "Your intake submission is being reviewed"
- No confirmation of appointment yet
- No session scheduled

#### Database State

**clients table:**
```sql
{
  id: <auto-generated>,
  name: '<filled from form>',
  email: '<optional from form>',
  phone: '<optional from form>',
  date_of_birth: '<optional from form>',
  status: 'intake',              -- Current state
  client_since: '<submission timestamp>',
  referral_source: '<from form>',
  notes: '<intake notes>',
  therapist_id: NULL,            -- Not assigned
  last_session_date: NULL,
  total_sessions_completed: 0,
  total_amount_paid: 0.00,
  is_recurring: false,
  created_at: '<timestamp>',
  updated_at: '<timestamp>'
}
```

**client_status_history table:**
```sql
{
  id: '<uuid>',
  client_id: <client id>,
  old_status: NULL,              -- First entry
  new_status: 'intake',
  changed_by_user_id: '<user id who submitted>',
  reason: 'Client intake form submitted',
  created_at: '<submission timestamp>'
}
```

#### Possible Next States
- ✅ `assessment_pending` - Clinician schedules assessment
- ✅ `inactive` - Clinician declines client
- ⚠️ `intake` - Remains in intake pending additional info

#### Cannot Transition Directly To (Invalid)
- ❌ `ready_for_booking` - Assessment not done
- ❌ `booking_scheduled` - No assessment
- ❌ `payment_pending` - No booking
- ❌ `active` - No session
- ❌ `completed` - No sessions conducted
- ❌ `booking_expired` - No booking exists

### 2. ASSESSMENT_PENDING

**Status Code:** `assessment_pending`  
**Initial State:** NO  
**Dead End State:** NO  
**Entry Points:**
- From `intake` (clinician schedules assessment)
- From `inactive` (clinician resumes client)

#### Definition
The **ASSESSMENT_PENDING** state indicates that a clinical assessment session has been scheduled or is in progress. The clinician is evaluating the client's suitability for therapy and determining the appropriate therapeutic approach.

#### What This Means

- ✅ Initial intake review complete
- ✅ Assessment appointment scheduled or in process
- ✅ Clinician actively evaluating client
- ✅ Determining therapy approach/modality
- ✅ Evaluating fit with therapist/clinic
- ❌ Therapy has not started
- ❌ No sessions scheduled yet
- ❌ No payments processed
- ❌ Therapist may not be assigned

#### Clinician Actions at This State

1. **Conduct clinical assessment:**
   - Meet with client (virtual or in-person)
   - Deep dive into presenting issues
   - Assess severity/urgency
   - Evaluate mental health status
   - Determine appropriate modality (individual/group/couple)
   - Assess safety (suicidal ideation, abuse, etc.)

2. **Collect detailed information:**
   - Full psychological history
   - Family dynamics
   - Work/relationship status
   - Coping mechanisms
   - Previous treatment outcomes
   - Current support system

3. **Diagnostic formulation:**
   - Preliminary diagnoses (if applicable)
   - Functional impairment level
   - Motivation for treatment
   - Realistic goals & expectations

4. **Treatment planning:**
   - Therapy approach (CBT, DBT, psychodynamic, etc.)
   - Estimated duration
   - Session frequency recommendation
   - Cost estimate
   - Potential challenges

5. **Therapist matching (optional):**
   - If multiple therapists available
   - Match based on specialization, personality fit
   - Check availability
   - Assign `therapist_id` field

#### Decision Point After Assessment

```
Assessment Complete
       ↓
├─ Client SUITABLE for therapy
│  ├─ Therapy approach clear
│  ├─ No contraindications
│  ├─ Client motivated
│  └─ → Change to 'ready_for_booking'
│
├─ Client NEEDS CRISIS SUPPORT
│  ├─ Immediate danger assessment
│  ├─ Safety planning
│  └─ → May stay in 'assessment_pending' or move to 'active'
│
├─ Client NOT SUITABLE
│  ├─ Assessment reveals need for different service
│  ├─ Referred elsewhere (psychiatry, medication, hospital)
│  └─ → Change to 'inactive' with reason noted
│
└─ UNCERTAIN / NEEDS MORE INFO
   ├─ Additional tests/evals needed
   ├─ Waiting for collateral info (family, previous therapist)
   └─ → Stay in 'assessment_pending'
```

#### Typical Duration
- **Minimum:** 1-2 hours (assessment itself)
- **Maximum:** Days to weeks (if follow-up assessments needed)
- **Typical:** 1-3 days (if appointment already scheduled)

#### Client-Facing Communication
- Confirmation: "Your assessment is scheduled for [Date] at [Time]"
- Reminder: "Your assessment is coming up in 24 hours"
- Waiting message: "Clinician is reviewing your assessment results"
- Confirmation after: "Your assessment is complete. We'll contact you shortly with next steps"

#### Database State

**clients table updates:**
```sql
{
  status: 'assessment_pending',  -- Changed from 'intake'
  therapist_id: NULL or '<assigned id>',  -- May be populated
  updated_at: '<timestamp>'
}
```

**client_status_history entry:**
```sql
{
  client_id: <id>,
  old_status: 'intake',
  new_status: 'assessment_pending',
  changed_by_user_id: '<clinician id>',
  reason: 'Assessment scheduled' or 'Assessment in progress',
  created_at: '<timestamp>'
}
```

#### Possible Next States
- ✅ `ready_for_booking` - Assessment complete, client approved
- ✅ `inactive` - Assessment reveals unsuitability
- ✅ `active` - (rare) Immediate therapy start with crisis client
- ⚠️ `assessment_pending` - Remains pending additional evaluation

#### Cannot Transition Directly To (Invalid)
- ❌ `intake` - Cannot go backwards
- ❌ `booking_scheduled` - No assessment outcome yet
- ❌ `payment_pending` - No session booked
- ❌ `completed` - No therapy conducted
- ❌ `booking_expired` - No booking exists

### 3. READY_FOR_BOOKING

**Status Code:** `ready_for_booking`  
**Initial State:** NO  
**Dead End State:** NO  
**Entry Points:**
- From `assessment_pending` (assessment completed, client approved)
- From `active` (therapy ended, client wants to continue with new modality)

#### Definition
The **READY_FOR_BOOKING** state indicates that the clinical assessment is complete, the client has been deemed suitable for therapy, and is now available to schedule their first (or subsequent) therapy session.

#### What This Means

- ✅ Clinical assessment complete
- ✅ Client approved for therapy
- ✅ Therapy approach determined
- ✅ Therapist assigned (in most cases)
- ✅ Treatment plan established
- ✅ Cost/fees discussed & agreed
- ❌ No session scheduled yet
- ❌ No bookings exist in system
- ❌ No payments processed

#### Clinician/Admin Actions at This State

1. **Prepare for booking:**
   - Confirm therapist availability
   - Verify client preferred time slots
   - Check room/resource availability
   - Set up therapist-client notes/records

2. **Client communication:**
   - Send treatment plan summary
   - Confirm fees/payment terms
   - Provide booking link/instructions
   - Answer final questions

3. **Administrative prep:**
   - Register client in scheduling system
   - Set up client file/records
   - Prepare intake documentation
   - Schedule first appointment (or enable client self-booking)

#### Who Takes Next Action?
- **Clinician/Admin:** Schedules session directly
- **Client:** Self-books available slots (if enabled)
- Either party can initiate session scheduling

#### Client Experience
- Can browse available therapist/time slots
- Can select preferred appointment time
- Receives confirmation with:
  - Date/time of appointment
  - Therapist name
  - Location (virtual/physical room)
  - Preparation instructions
  - Cost/payment info
  - How to reschedule/cancel

#### Typical Duration
- **Minimum:** Minutes (if booked immediately)
- **Maximum:** Weeks (if waiting for therapist availability)
- **Typical:** 2-7 days (between assessment & first session)

#### Payment Status at This State
- Not yet charged
- Cost has been communicated
- Payment method may be collected
- Payment scheduled for after session (or prepaid model)

#### Database State

**clients table:**
```sql
{
  status: 'ready_for_booking',   -- Changed from 'assessment_pending'
  therapist_id: '<assigned therapist id>',
  updated_at: '<timestamp>'
}
```

**client_status_history entry:**
```sql
{
  client_id: <id>,
  old_status: 'assessment_pending',
  new_status: 'ready_for_booking',
  changed_by_user_id: '<clinician id>',
  reason: 'Assessment complete. Client approved for therapy.' OR 
          'Client suitable for therapy. Ready for booking.',
  created_at: '<timestamp>'
}
```

#### Possible Next States
- ✅ `booking_scheduled` - First session booked
- ✅ `inactive` - Client declines/postpones (moves to waiting list)
- ⚠️ `ready_for_booking` - Remains if waiting for client decision

#### Cannot Transition Directly To (Invalid)
- ❌ `intake` - Cannot go backwards
- ❌ `assessment_pending` - Assessment already complete
- ❌ `payment_pending` - Must book first
- ❌ `active` - Must have booking first
- ❌ `completed` - No sessions conducted
- ❌ `booking_expired` - No booking exists yet

### 4. BOOKING_SCHEDULED

**Status Code:** `booking_scheduled`  
**Initial State:** NO  
**Dead End State:** NO  
**Entry Points:**
- From `ready_for_booking` (client books session)
- From `payment_pending` (rescheduled after payment)
- From `inactive` (client resumes after pause)

#### Definition
The **BOOKING_SCHEDULED** state indicates that a therapy session has been scheduled/confirmed. The client has a confirmed appointment with their assigned therapist at a specific date and time.

#### What This Means

- ✅ Therapy session booked
- ✅ Date/time confirmed
- ✅ Therapist assigned
- ✅ Room/location assigned
- ✅ First session has a confirmed start date
- ⚠️ Session may be awaiting payment
- ❌ Session has not occurred yet
- ❌ No session notes created
- ❌ No completion recorded

#### Session Details at This State

A `booking` record is created in the database with:

```sql
{
  id: '<booking id>',
  client_id: <client id>,
  therapist_id: <therapist id>,
  session_date: '<2026-06-20 14:00:00>',
  session_duration_minutes: 60,
  session_type: 'single' or 'group' or 'couple',
  room_id: '<assigned room>',
  booking_status: 'scheduled' or 'confirmed',
  payment_status: 'pending' or 'paid',
  payment_deadline: '<deadline if applicable>',
  created_at: '<timestamp>',
  updated_at: '<timestamp>'
}
```

#### Pre-Session Activities

1. **Therapist prepares:**
   - Reviews client intake/assessment notes
   - Prepares session plan
   - Sets up room/technology (if virtual)
   - Blocks calendar time

2. **Client receives:**
   - Session confirmation email
   - Calendar invite
   - Pre-session questionnaire (optional)
   - Preparation instructions
   - Virtual link (if applicable)
   - How to prepare for session
   - Payment reminder (if not yet paid)

3. **Administrative:**
   - Confirm payment method
   - Send invoice/payment request
   - Prepare session room
   - Set up recording (if applicable)
   - Finalize consent forms

#### Possible Payment Scenarios at This State

**Scenario 1: Prepayment Required**
```
Booking scheduled → Awaiting prepayment → Move to 'payment_pending'
  ↓
Payment received → Move back to 'booking_scheduled'
  ↓
Session occurs
```

**Scenario 2: Payment After Session**
```
Booking scheduled (no prepayment) → Session occurs → Payment collected
```

**Scenario 3: Subscription/Insurance**
```
Booking scheduled (covered by plan) → Session occurs → Auto-billed
```

#### Typical Duration
- **Minimum:** Hours (if booked same day)
- **Maximum:** 30+ days (if therapist availability far out)
- **Typical:** 3-14 days (between booking and session)

#### Client-Facing Status
- Website: "Your appointment is confirmed for [Date] at [Time]"
- Notification: "Your session with [Therapist] is scheduled"
- Reminder: "Your appointment is tomorrow at [Time]"
- Option to: Reschedule / Cancel / Confirm attendance

#### Database State

**clients table:**
```sql
{
  status: 'booking_scheduled',   -- Changed from 'ready_for_booking'
  therapist_id: '<therapist id>',
  updated_at: '<timestamp>'
}
```

**bookings table (new):**
```sql
{
  id: '<auto id>',
  client_id: <client id>,
  therapist_id: <therapist id>,
  session_date: '2026-06-20 14:00:00',
  session_type: 'single',
  booking_status: 'scheduled',
  payment_status: depends on scenario,
  room_id: '<room id>',
  created_at: '<timestamp>'
}
```

**client_status_history entry:**
```sql
{
  client_id: <id>,
  old_status: 'ready_for_booking',
  new_status: 'booking_scheduled',
  changed_by_user_id: '<admin/system>',
  reason: 'First session booked for [date/time]',
  created_at: '<timestamp>'
}
```

#### Possible Next States
- ✅ `payment_pending` - If payment required before session
- ✅ `active` - Session occurs → Immediately transitions
- ✅ `inactive` - Client cancels booking
- ✅ `booking_expired` - Booking window expires without completion
- ⚠️ `booking_scheduled` - Remains until session occurs

#### Cannot Transition Directly To (Invalid)
- ❌ `intake` - Cannot go backwards
- ❌ `assessment_pending` - Assessment already complete
- ❌ `ready_for_booking` - Already booked
- ❌ `completed` - Session hasn't occurred
- ❌ `payment_pending` - Only if payment gate exists

### 5. PAYMENT_PENDING

**Status Code:** `payment_pending`  
**Initial State:** NO  
**Dead End State:** NO (unless abandoned)  
**Entry Points:**
- From `booking_scheduled` (if prepayment required)
- From `payment_pending` (rescheduled payment deadline)

#### Definition
The **PAYMENT_PENDING** state indicates that a session is booked but payment has not yet been received. The session is held or scheduled to start only after successful payment.

#### What This Means

- ✅ Session is booked
- ✅ Date/time confirmed
- ❌ Payment not received
- ❌ Session cannot proceed until paid
- ❌ Therapist not yet "locked in"
- ⚠️ Payment deadline is approaching/past

#### When This State Is Used

**Clinic Policy Examples:**

1. **Prepayment Model:**
   ```
   Clinic requires payment before session
   Booking Created → Payment Pending (1-2 days) → Payment Received → Active
   ```

2. **Insurance/Split Payment:**
   ```
   Client pays copay, insurance pays balance
   Booking Created → Payment Pending (clearing insurance) → Active
   ```

3. **High-Risk Client:**
   ```
   Client history of no-shows
   Clinic requires upfront payment to reduce risk
   Booking → Payment Pending
   ```

4. **Promotional/Discounted Rate:**
   ```
   Special pricing requires advance payment
   Booking → Payment Pending (confirm payment for discount)
   ```

#### Payment Details at This State

```sql
bookings table:
{
  id: '<booking id>',
  client_id: <client id>,
  therapist_id: <therapist id>,
  session_date: '2026-06-20 14:00:00',
  payment_status: 'pending',     -- CRITICAL
  payment_deadline: '2026-06-19 23:59:59',  -- By this time
  amount: 150.00,
  currency: 'USD',
  payment_method: 'credit_card' or 'bank_transfer' or 'cash',
  payment_date: NULL,            -- Not yet paid
  marked_paid_at: NULL
}
```

#### Client Actions at This State

1. **Make payment:**
   - Online payment portal
   - Bank transfer
   - Credit/debit card
   - Check (mailed)
   - Cash (in-person)
   - Insurance submission

2. **Request postponement:**
   - Contact clinic
   - Request payment deadline extension
   - Request session delay
   - Discuss financial hardship

3. **Cancel booking:**
   - If unable to pay
   - Refund policy applies

#### Clinician/Admin Actions at This State

1. **Payment collection:**
   - Send invoice/payment request
   - Accept payment methods
   - Confirm receipt
   - Record in system

2. **Follow-up:**
   - Reminder 24 hours before deadline
   - Day-of reminder
   - Past deadline follow-up

3. **Escalation if no payment:**
   - Contact client (1st attempt)
   - Check if payment processing (2nd attempt)
   - Cancel booking if deadline passed
   - Move to `booking_expired`

#### Typical Duration
- **Minimum:** Minutes (if paid immediately)
- **Maximum:** Depends on deadline (typically 1-3 days)
- **Typical:** 1 day (payment expected by day before session)

#### Compliance & Data

```sql
payment_records table (when paid):
{
  id: '<payment record id>',
  booking_id: <booking id>,
  client_id: <client id>,
  therapist_id: <therapist id>,
  amount_paid: 150.00,
  charge_status: 'pending' (awaiting confirmation),
  payment_date: NOW(),
  marked_by_user_id: '<admin who recorded>',
  created_at: NOW()
}
```

#### Possible Next States
- ✅ `active` - Payment received → Session can proceed
- ✅ `booking_expired` - Payment deadline passed without payment
- ✅ `inactive` - Client cancels
- ⚠️ `payment_pending` - Remains until resolved

#### Cannot Transition Directly To (Invalid)
- ❌ `intake` - Cannot go backwards
- ❌ `assessment_pending` - Assessment done
- ❌ `ready_for_booking` - Already booked
- ❌ `booking_scheduled` - Already in payment pending state
- ❌ `completed` - Session hasn't started

#### If Payment Never Comes

```
Payment Pending (deadline: 2026-06-19)
       ↓
       ↓ (deadline passes, no payment)
       ↓
Booking Expired (dead state)
       ↓
Client contacted: "Your session was cancelled due to lack of payment"
       ↓
Therapist notified: "Session cancelled, will be rescheduled if payment received"
       ↓
Admin: May move to 'inactive' or delete booking
```

### 6. ACTIVE

**Status Code:** `active`  
**Initial State:** NO  
**Dead End State:** NO  
**Entry Points:**
- From `booking_scheduled` (session about to start, no payment gate)
- From `payment_pending` (payment received)

#### Definition
The **ACTIVE** state indicates that the client is currently engaged in therapy. At least one therapy session is occurring or has occurred. The client is actively receiving mental health treatment.

#### What This Means

- ✅ Session has started/is in progress OR just occurred
- ✅ Client receiving active therapy
- ✅ Therapist actively treating client
- ✅ May be in first session or continuation
- ✅ May have multiple sessions scheduled
- ✅ Session notes being recorded
- ✅ Payment processed (or will be after session)

#### Multiple Scenarios in ACTIVE State

**Scenario 1: Single Session Client**
```
Only 1 session booked
Session occurs
Status: active
Next session to be scheduled
```

**Scenario 2: Recurring Client (is_recurring = true)**
```
Multiple sessions already booked (weekly, bi-weekly, etc.)
Session occurs
Status: active
Next sessions already scheduled
is_recurring: true
Client maintains regular appointment slot
```

**Scenario 3: Ongoing Therapy**
```
Open-ended therapy relationship
New sessions scheduled as needed
Status: active
Therapist may update treatment plan
Client expected to continue indefinitely
```

#### Session Management at This State

**During Session:**
- Therapist takes notes
- Monitors progress
- Adjusts treatment as needed
- Explores issues in depth
- Assigns homework/exercises
- Schedules next session

**After Session:**
- Therapist completes session notes
- Records outcomes & progress
- Updates client file
- Documents any changes/concerns
- Schedules follow-up

#### Session Notes Recording

```sql
session_notes table:
{
  id: '<note id>',
  booking_id: <booking id>,
  therapist_id: <therapist id>,
  notes: '<clinical session notes>',
  session_outcome: 'productive' or 'partial' or 'challenging',
  progress_score: 3 (on scale 1-5),
  created_at: NOW(),
  updated_at: NOW()
}
```

#### Client Experience at This State
- Attending scheduled sessions
- Engaging in therapeutic work
- Receiving treatment
- May start seeing improvement
- Developing relationship with therapist
- Learning coping strategies
- May have homework/assignments

#### Payment Processing at This State

**Option 1: Payment After Session**
```
Session occurs
Therapist marks session complete
Admin records payment received
Payment processed
Invoice sent to client
```

**Option 2: Prepaid/Subscription**
```
Client paid upfront
Session occurs
Amount deducted from balance
Invoice/receipt generated
```

**Option 3: Insurance Claim**
```
Session occurs
Therapist submits to insurance
Waiting for insurance processing
Client may receive bill for copay/deductible
```

#### Transition Possibilities

**Multiple Sessions Already Booked:**
```
Active (Session 1 complete)
  ↓ (Session 2 occurs automatically)
  ↓
Active (continues) - Status doesn't change
```

**One Session Only:**
```
Active (Session 1 complete)
  ↓ (Awaiting next booking or decision)
  ↓
├─ Next session booked → Ready for next session
├─ Therapy paused → Move to 'inactive'
└─ Therapy concluded → Move to 'completed'
```

#### Recurring vs. One-Time Clients

**Recurring Client (is_recurring = true):**
- Regular appointment slot (e.g., Tuesdays at 3 PM)
- Stays in 'active' indefinitely
- Sessions continue until paused/completed
- No action needed between sessions
- Therapist carries ongoing relationship

**One-Time/Episodic (is_recurring = false):**
- Single session or limited package
- May transition to 'completed' after each session
- Requires re-booking for next session
- Can move to 'inactive' between episodes

#### Database State

**clients table:**
```sql
{
  status: 'active',              -- In therapy
  therapist_id: '<therapist id>',
  is_recurring: true or false,   -- Type of client
  total_sessions_completed: 1+,  -- Increments
  last_session_date: '2026-06-20 15:00:00',
  updated_at: NOW()
}
```

**bookings table (current session):**
```sql
{
  booking_status: 'completed' or 'confirmed',
  session_date: '<date of last/current session>',
  marked_paid_at: '<timestamp when payment processed>'
}
```

**session_notes table (after session):**
```sql
{
  notes: '<therapist clinical notes>',
  session_outcome: 'productive',
  progress_score: 3
}
```

#### Possible Next States
- ✅ `active` - Remains (next session occurs)
- ✅ `completed` - Therapy ends after final session
- ✅ `inactive` - Client puts therapy on pause
- ⚠️ `active` - Continues if recurring

#### Cannot Transition Directly To (Invalid)
- ❌ `intake` - Cannot go backwards
- ❌ `assessment_pending` - Assessment already complete
- ❌ `ready_for_booking` - Already in therapy
- ❌ `booking_scheduled` - Already in therapy
- ❌ `payment_pending` - Already paying
- ❌ `booking_expired` - Session already occurred

### 7. COMPLETED

**Status Code:** `completed`  
**Initial State:** NO  
**Dead End State:** USUALLY (can be reopened in rare cases)  
**Entry Points:**
- From `active` (final session occurs, therapy ends)
- From `inactive` (after pause period if therapeutic goals met)

#### Definition
The **COMPLETED** state indicates that the client's course of therapy has concluded. All agreed-upon therapy goals have been achieved or the client and therapist have mutually decided to end the therapeutic relationship.

#### What This Means

- ✅ Therapy treatment completed
- ✅ Final session occurred
- ✅ Treatment plan goals addressed
- ✅ Discharge/closing session completed
- ✅ Final session notes documented
- ✅ All payments processed
- ❌ No future sessions scheduled
- ❌ No active treatment ongoing

#### Reasons for Completion

**1. Goals Achieved**
```
Client came in with: Anxiety disorder
Treatment: CBT-based anxiety management
Outcome: Client managing symptoms independently
Termination: Therapy goals met, can function autonomously
→ COMPLETED
```

**2. Client-Initiated Termination**
```
Client decides: "I feel ready to stop"
Reason: Feeling better, cost, time, change in life circumstances
Process: Termination session scheduled
Therapist: Processes ending, provides resources
→ COMPLETED
```

**3. Therapist-Recommended Termination**
```
Scenario: Client showing consistent improvement
Therapist: "You've made excellent progress. Let's plan for closure."
Plan: 2-4 week wind-down period
Final session: Relapse prevention, resources provided
→ COMPLETED
```

**4. Mutual Decision**
```
Therapist & Client: "We've made good progress, time to close"
Both agree: Therapy has addressed primary issues
Plan: Structured termination over 1-2 sessions
→ COMPLETED
```

**5. Extended Treatment Reached**
```
Therapist: "Our agreed 10-session package is complete"
Progress: Made gains, can continue independently
Offer: Option to continue with new goals
Client: "I'll take a break, may return later"
→ COMPLETED (can return later → ACTIVE)
```

#### Discharge Planning

In the session(s) leading to completion:

1. **Review progress:**
   - Assess achievement of goals
   - Discuss changes/improvements
   - Review coping skills learned
   - Evaluate client confidence

2. **Relapse prevention:**
   - Identify potential triggers
   - Develop maintenance plan
   - Provide coping resources
   - Crisis contact information

3. **Transition planning:**
   - Discuss life after therapy
   - Ongoing self-care plan
   - Other resources (support groups, etc.)
   - When/how to seek help again

4. **Documentation:**
   - Final session notes
   - Summary of treatment
   - Discharge summary
   - Recommendations for future

5. **Practical matters:**
   - Final invoice/payment
   - Records transfer (if needed)
   - Certificate of completion (if applicable)

#### Client Experience at This State
- Final session completed
- May feel: Relief, gratitude, slight sadness at ending
- Receives: Summary of treatment, resource list
- Encouraged to: Continue self-care, contact if relapse
- Option to: Return in future if needed

#### Archiving & Records

- Client record remains in system
- Historic data preserved

#### Post-Completion Communication
- Email: "Thank you for completing your therapy with us"
- May include: Course evaluation, feedback request
- Resources: List of support services, crisis lines
- Door-open: "We're here if you need us in the future"

#### Possible Next States
- ✅ `completed` - Remains (terminal state usually)
- ✅ `active` - If client returns with new goals → rare reopening
- ✅ `inactive` - If client wants to keep options open but take break

#### Cannot Transition Directly To (Invalid)
- ❌ `intake` - Cannot go backwards
- ❌ `assessment_pending` - Already completed therapy
- ❌ `ready_for_booking` - Therapy finished
- ❌ `booking_scheduled` - Therapy finished
- ❌ `payment_pending` - Already paid
- ❌ `booking_expired` - Therapy already completed

#### Can This State Be Reversed?

**Theoretical:** Yes, if client returns with new goals
```
Completed (therapy ended 6 months ago)
Client returns: "I have new issues to address"
Path: intake → assessment → active again
Or direct: Completed → Assessment pending → Active (expedited)
```

**Practical:** Rare, but possible
- Most treated as new intake
- Some clinics expedite returning clients
- Therapeutic relationship already established

### 8. INACTIVE

**Status Code:** `inactive`  
**Initial State:** NO  
**Dead End State:** NO (can be resumed)  
**Entry Points:**
- From `intake` (clinician decides not to take client)
- From `assessment_pending` (client not suitable)
- From `booking_scheduled` (client requests pause)
- From `active` (therapy pause/hold)
- From `completed` (client may want to preserve option)

#### Definition
The **INACTIVE** state represents a pause in the therapeutic relationship. The client is not currently in therapy, but the door is open to resume. This may be temporary (vacation, financial hardship) or indefinite (low priority, client on waiting list).

#### Scenarios Leading to INACTIVE

**Scenario 1: Not Currently Suitable (After Intake)**
```
New client submits intake
Clinician reviews: "Client needs psychiatry first"
Decision: Refer to psychiatrist, pause therapy
Status: Inactive
Reason: "Requires medication evaluation before therapy"
→ Client referred, can return after psychiatry evaluation
```

**Scenario 2: Assessment Reveals Unsuitability**
```
Assessment completed
Findings: Client needs inpatient treatment for acute crisis
Decision: Not appropriate for outpatient therapy right now
Status: Inactive
Reason: "Client requires higher level of care"
→ Follow-up in 3 months, reassess
```

**Scenario 3: Client Requests Pause from Active Therapy**
```
Client in active therapy, 5 sessions completed
Client says: "I need a break. Work is crazy right now."
Decision: Support pause, maintain relationship
Status: Inactive (from Active)
Plan: Check in monthly, resume when ready
```

**Scenario 4: Financial Hardship**
```
Client in active therapy
Job loss/financial crisis occurs
Client: "Can't afford sessions right now"
Decision: Pause rather than terminate
Status: Inactive
Plan: Resume when financial situation improves
```

**Scenario 5: Long Waiting List**
```
Many suitable clients, limited therapist availability
New client assessed & approved: "Suitable for therapy"
But: No therapist available for 2 months
Status: Inactive (with notation: "waiting list")
Plan: Move to Active when therapist becomes available
```

#### Difference from COMPLETED

| Aspect | COMPLETED | INACTIVE |
|--------|-----------|----------|
| **Intent** | Therapy ended | Therapy paused |
| **Finality** | Permanent (usually) | Temporary (usually) |
| **Reopening** | Rare, requires new intake | Straightforward, resume |
| **Session notes** | Final discharge notes | Last session date recorded |
| **Next steps** | Complete, no plan | Can resume on timeline |

#### Clinical Management of Inactive Clients

**Follow-up Plan:**
```
Client moves to Inactive
  ↓
Set followup date (30/60/90 days)
  ↓
Clinician sends: "Checking in, ready to resume?"
  ↓
├─ Client wants to resume
│  └─ Assess current status
│     └─ Move to Active or Assessment Pending
│
├─ Client wants to stay inactive longer
│  └─ Set new followup date
│
└─ Client wants to terminate
   └─ Move to Completed
```

#### Types of Inactivity

**Inactive - Temporarily on Hold**
```
Reason: "Client taking 2-month break for family issues"
Expected Resume: September 2026
Plan: Check in August, resume in September
```

**Inactive - Waiting List**
```
Reason: "Suitable for therapy, no therapist available"
Expected Resume: When therapist opens slot
Plan: Contact when therapist available
```

**Inactive - Declined Service**
```
Reason: "Client not suitable, referred to psychiatry"
Expected Resume: After psychiatric evaluation
Plan: Psychiatry will refer back if appropriate
```

**Inactive - Client Moved**
```
Reason: "Client relocated to another city"
Expected Resume: Unknown
Plan: Transfer records if requested, offer resources in new location
```

**Inactive - Could Resume Anytime**
```
Reason: "Therapy on indefinite pause"
Expected Resume: Unknown
Plan: Client can call to schedule anytime
```

#### Client Communication about Inactive Status
- Explanation: "Your account is on pause"
- Not: "You're fired" or "Never come back"
- Message: "We're here when you're ready"
- Door: "Contact us whenever you want to resume"
- Resources: List of community resources while paused

#### Database State

**clients table:**
```sql
{
  status: 'inactive',            -- On pause
  therapist_id: '<previous therapist>' or NULL,
  total_sessions_completed: <count>,  -- Preserved
  last_session_date: '<last session date>',
  updated_at: NOW()
}
```

**client_status_history entry:**
```sql
{
  old_status: 'intake' or 'assessment_pending' or 'active' or 'completed',
  new_status: 'inactive',
  reason: 'Client requested pause' OR
          'Awaiting psychiatry evaluation' OR
          'Temporarily on hold - financial' OR
          'Waiting list due to therapist availability' OR
          'Client moved',
  changed_by_user_id: '<clinician id>',
  created_at: NOW()
}
```

#### Note Field in Database

```sql
-- Can include next steps:
notes: 'Paused 2026-06-10. Check in 2026-07-10. 
        Resume active therapy after client returns from sabbatical.
        Last therapist: Jane Smith. Contact: jane@clinic.com'
```

#### Possible Next States
- ✅ `assessment_pending` - Client reassessed after time off
- ✅ `active` - Client resumes therapy (expedited)
- ✅ `completed` - Client decides to terminate instead
- ✅ `inactive` - Remains indefinitely
- ✅ `intake` - (rare) Completely restart if new therapist/issues

#### Cannot Transition Directly To (Invalid)
- ❌ `booking_scheduled` - Must be active first
- ❌ `payment_pending` - Must be active first
- ❌ `ready_for_booking` - Assessment not current

#### Reopening an Inactive Client

**Process When Client Calls to Resume:**

```
Call: "Hi, I was a patient. I'd like to resume therapy."
  ↓
Clinic: Locates inactive record
  ↓
Clinician: Reviews notes from inactive period
  ↓
├─ If minimal time passed & situation unchanged:
│  └─ Direct move: Inactive → Active (reschedule)
│
└─ If significant time/change:
   └─ Quick reassessment: Inactive → Assessment Pending → Active
```

**Practical Scenario:**
```
June 10: Client moves to Inactive (financial hardship)
August 1: Client calls: "Job situation resolved, want to resume"
Clinician: "Great! Let's schedule a brief check-in (30 min)"
Check-in: Confirms client situation stable, goals unchanged
Status change: Inactive → Active
Booking: Schedule session for following week
```

### 9. BOOKING_EXPIRED

**Status Code:** `booking_expired`  
**Initial State:** NO  
**Dead End State:** YES (booking is lost)  
**Entry Points:**
- From `payment_pending` (payment deadline passes without payment)
- From `booking_scheduled` (appointment date passes without session)

#### Definition
The **BOOKING_EXPIRED** state indicates that a scheduled session booking has expired and is now invalid. This is a dead-end state from which the system does not automatically transition - manual intervention required to restart.

#### Causes of Booking Expiration

**Cause 1: Payment Deadline Passed**
```
Booking created with payment_deadline: 2026-06-19
State: payment_pending
June 19 passes → No payment received
June 20 morning: System detects deadline passed
Action: Move to booking_expired
Reason: "Payment deadline expired without payment"
```

**Cause 2: Session Date Passed Without Completion**
```
Booking created with session_date: 2026-06-20 14:00
State: booking_scheduled
June 20 14:00 passes → No session recorded
June 21: Admin reviews, session never occurred
Action: Move to booking_expired
Reason: "Session date passed without completion"
```

**Cause 3: Client No-Show (Unresolved)**
```
Session scheduled: 2026-06-20 14:00
Client doesn't show up
Therapist waits 15 minutes, closes room
Booking not marked completed
June 21: Admin moves to expired
Reason: "Client no-show, session not completed"
```

**Cause 4: Clinic Cancellation (Not Rescheduled)**
```
Therapist becomes ill, must cancel session
Session date: 2026-06-20
Clinic attempts to reschedule but can't reach client
2 weeks pass without rescheduling
Admin: Move to expired
Reason: "Clinic cancellation - unable to reschedule"
```

#### What NOT To Confuse This With

| State | What Happens |
|-------|--------------|
| **booking_scheduled** | Session is booked, upcoming |
| **payment_pending** | Payment not yet received, session on hold |
| **active** | Session is happening or just happened |
| **booking_expired** | Deadline/date passed, opportunity lost |
| **completed** | Session successfully completed |

#### Client Impact of Booking Expired

**Before Expiration:**
- Client has confirmed appointment
- Therapist has reserved time
- Room is allocated
- Payment expected/collected

**After Expiration:**
- Appointment is cancelled
- Therapist time is freed up
- Session cannot occur on original date
- Client must rebook if they want to continue
- May lose payment (depends on cancellation policy)

#### Clinic Impact

**From Clinic Perspective:**
```
Booking expired = Therapist time slot becomes available again
Can be re-booked for different client
Or: Offered back to original client if they can reschedule
```

#### Database State

**clients table:**
```sql
{
  status: 'booking_expired',     -- Dead end
  therapist_id: '<previous therapist>' or NULL,
  total_sessions_completed: <unchanged>,
  last_session_date: <unchanged>,
  updated_at: NOW()
}
```

**bookings table (expired booking):**
```sql
{
  booking_status: 'cancelled' or 'expired',
  payment_status: 'pending' or 'refunded',
  cancellation_reason: 'Payment deadline expired' OR
                       'Session not completed by deadline' OR
                       'Client no-show',
  cancelled_at: NOW()
}
```

**client_status_history entry:**
```sql
{
  old_status: 'payment_pending' or 'booking_scheduled',
  new_status: 'booking_expired',
  reason: 'Payment deadline not met' OR
          'Session date passed without completion' OR
          'Booking cancelled - unable to reschedule',
  changed_by_user_id: '<admin id>',
  created_at: NOW()
}
```

#### Payment/Refund Policy at Booking Expired

**Scenario 1: Payment Was Made**
```
Client paid before deadline ✓
Session expired without occurring ✗
Refund options:
  a) Full refund to original payment method
  b) Credit toward future sessions
  c) Non-refundable per policy (clinic policy dependent)
```

**Scenario 2: Payment Not Yet Made**
```
Payment pending
Booking expires
Session cancelled
Result: No charge to client
```

**Scenario 3: Partial Payment**
```
Client prepaid 50%, balance due day-of
Booking expires before payment date
Clinic: Refunds prepaid amount
Client: Can rebook and repay if interested
```

#### Recovery Process from Booking Expired

**Option 1: Direct Contact**
```
Clinic calls client:
"Your booking with us expired on June 20.
Would you like to reschedule?"
  ↓
If YES: Create new booking → status depends on scenario
If NO: Move to 'inactive' or 'completed'
```

**Option 2: Email/SMS Campaign**
```
Automated: "Your appointment opportunity has expired"
Reminder: "We'd love to work with you. Rebook here."
Link: Self-service rescheduling
```

**Option 3: Manual Admin Follow-up**
```
Admin: Reviews expired bookings weekly
Action: Contact clients, attempt to reschedule
Result: Successfully reboot or move to inactive
```

#### Possible Next States from Booking Expired

- ✅ `booking_scheduled` - If rebooked successfully (creates new booking)
- ✅ `inactive` - If client doesn't respond/reschedule
- ✅ `completed` - If decided not to pursue (rare)
- ✅ `booking_expired` - Remains if no action taken

#### Cannot Transition Directly To (Invalid)
- ❌ `intake` - Cannot go backwards
- ❌ `assessment_pending` - Assessment already done
- ❌ `ready_for_booking` - Would need re-booking, not just state change
- ❌ `active` - Session never happened
- ❌ `payment_pending` - Would need new booking

#### Best Practices to Prevent Booking Expiration

**From Clinic Side:**
1. Set clear payment deadlines (at least 48 hours before)
2. Send reminders (24h, 6h, 1h before appointment)
3. Allow rescheduling up to certain point
4. Have automatic email if no-show
5. Timely follow-up within 24 hours

**From Client Side:**
1. Confirm appointment time (calendar invite)
2. Set phone reminder
3. Plan transportation/tech (if virtual)
4. Have payment ready
5. Call clinic if unable to attend

### Transition API Endpoint

**Endpoint:** `PUT /api/admin/clients/[id]/status`

**Request:**
```json
{
  "new_status": "assessment_pending",
  "reason": "Optional reason for transition"
}
```

**Validation:**
```typescript
1. Check new_status is in VALID_STATUSES array
2. Check user has 'manage_clients' permission
3. Get current client status
4. Verify new_status ≠ current status
5. Update clients table with new status
6. Insert into client_status_history
7. Log audit action
8. Return 200 with updated status
```

**Error Responses:**
```json
// Invalid status
{
  "error": "Invalid new_status. Must be one of: intake, assessment_pending, ..."
}

// Missing permission
{
  "error": "Insufficient permissions"
}

// Client not found
{
  "error": "Client not found"
}

// Status already at target
{
  "error": "Client status is already 'assessment_pending'"
}
```

## Transition Decision Trees

### Decision Tree 1: From INTAKE → What's Next?

```
┌─ INTAKE (New client just submitted form)
│
└─ CLINICIAN DECISION: Review intake information
   │
   ├─ Is client information complete? ───┐
   │                                      │
   │  YES ──────────────────────────────────┤
   │  NO ─ Request more info ──────────────┤
   │      (stay in intake)                 │
   │                                       │
   │                                       ↓
   │  Ready to assess? ──┐
   │                     │
   │  YES ──────────────┼─→ Is client appropriate? ───┐
   │  NO (more time needed) ┘                         │
   │      (stay in intake)                            │
   │                                                  ↓
   │                                          YES → ASSESSMENT_PENDING
   │                                          NO → INACTIVE
   │
   └─ POSSIBLE REASONS TO REJECT (→ INACTIVE)
      • Client needs psychiatry first
      • Not appropriate for outpatient therapy
      • Too crisis/severe for clinic
      • Client changed mind
      • No availability for months
```

### Decision Tree 2: From ASSESSMENT_PENDING → What's Next?

```
┌─ ASSESSMENT_PENDING (Clinician evaluating client)
│
└─ ASSESSMENT COMPLETE
   │
   ├─ Is client suitable for therapy?
   │  │
   │  ├─ YES (Assessment clear, approach determined)
   │  │  └─ READY_FOR_BOOKING
   │  │
   │  ├─ UNCERTAIN (Need more info/testing)
   │  │  └─ ASSESSMENT_PENDING (continue assessing)
   │  │
   │  └─ NO (Not appropriate for this clinic)
   │     ├─ Referred elsewhere? → INACTIVE (with referral)
   │     ├─ Crisis intervention needed? → ACTIVE or refer
   │     └─ Not suitable? → INACTIVE (with reason)
   │
   └─ SPECIAL CASE: Crisis discovered
      └─ Can go directly to ACTIVE (crisis therapy starts)
```

### Decision Tree 3: From READY_FOR_BOOKING → What's Next?

```
┌─ READY_FOR_BOOKING (Client approved, awaiting appointment)
│
├─ Is client ready to book?
│  │
│  ├─ YES (Client books session)
│  │  └─ BOOKING_SCHEDULED (appointment confirmed)
│  │
│  ├─ NO (Client delays/postpones)
│  │  └─ INACTIVE (keep on waiting list)
│  │
│  └─ ASKING QUESTIONS/HESITANT
│     └─ READY_FOR_BOOKING (wait for client)
│
└─ ADMIN ACTION: Contact client to move forward
   ├─ If client ready → BOOKING_SCHEDULED
   └─ If client not responding → INACTIVE
```

### Decision Tree 4: From BOOKING_SCHEDULED → What's Next?

```
┌─ BOOKING_SCHEDULED (Session appointment confirmed)
│
├─ Does payment prerequisite apply?
│  │
│  ├─ YES (Clinic requires prepayment)
│  │  └─ PAYMENT_PENDING
│  │
│  └─ NO (Pay after session)
│     └─ ACTIVE (session occurs)
│
├─ Session datetime approaches
│  │
│  ├─ Session occurs & completed
│  │  └─ ACTIVE
│  │
│  ├─ Client cancels before session
│  │  └─ INACTIVE
│  │
│  └─ Session date/time passes without completion
│     └─ BOOKING_EXPIRED
│
└─ PAYMENT_PENDING → (payment handling)
   ├─ Payment received
   │  └─ ACTIVE (session can proceed)
   │
   ├─ Payment deadline passes
   │  └─ BOOKING_EXPIRED (missed deadline)
   │
   └─ Client cancels
      └─ INACTIVE
```

### Decision Tree 5: From ACTIVE → What's Next?

```
┌─ ACTIVE (Client in therapy, sessions occurring)
│
├─ Does client have more sessions scheduled?
│  │
│  ├─ YES (Recurring or multiple bookings)
│  │  └─ ACTIVE (continues, status unchanged)
│  │
│  └─ NO (Single session only)
│     │
│     └─ What next?
│        ├─ Client wants to continue
│        │  └─ Book next session, remain ACTIVE
│        │
│        ├─ Client wants to pause
│        │  └─ INACTIVE
│        │
│        └─ Therapy complete (goals met)
│           └─ COMPLETED
│
└─ THERAPY GOALS & PROGRESS
   ├─ Goals being addressed, progress made
   │  └─ Continue in ACTIVE
   │
   ├─ Client hits plateau or new issues
   │  └─ Reassess treatment, may stay ACTIVE or change approach
   │
   ├─ Client wants to stop
   │  └─ Final session scheduled
   │     └─ COMPLETED
   │
   └─ Crisis/emergency
      ├─ May be referred to higher care
      └─ Temporarily stay ACTIVE with safety plan
```

### Decision Tree 6: From COMPLETED → What's Next?

```
┌─ COMPLETED (Therapy ended, goals achieved)
│
├─ Client wants to return (months/years later)
│  │
│  ├─ New issues, different goals
│  │  └─ INTAKE or ASSESSMENT_PENDING (assess new situation)
│  │
│  └─ Same issues recurring
│     └─ ASSESSMENT_PENDING (expedited re-evaluation)
│
├─ Client needs resources post-therapy
│  └─ Provide referrals, maintain COMPLETED
│
└─ No contact expected (closed)
   └─ Remain COMPLETED (archive if policy allows)
```

## State Timing & Duration

### Typical Timeline from Intake to Active

```
INTAKE ─────────► ASSESSMENT_PENDING ─────► READY_FOR_BOOKING ──► BOOKING_SCHEDULED ──► ACTIVE
│                 │                         │                    │
│                 │                         │                    │
Duration: 0 days  Duration: 1-3 days       Duration: 2-7 days  Duration: 1-14 days

Total elapsed time from intake to active:
├─ Best case (expedited): 2-3 days
├─ Typical case: 1-2 weeks
└─ Slow case (low clinic capacity): 2-4 weeks
```

### Duration by State (Typical Ranges)

| State | Minimum | Typical | Maximum |
|-------|---------|---------|---------|
| **intake** | Minutes | 1-3 days | 2-4 weeks |
| **assessment_pending** | 1 hour | 1-3 days | 2-4 weeks |
| **ready_for_booking** | Minutes | 2-7 days | Weeks (waiting list) |
| **booking_scheduled** | 1 hour | 2-14 days | Until session date |
| **payment_pending** | Minutes | 1 day | 2-3 days (deadline) |
| **active** | 1 hour | 2+ weeks | Months/years |
| **completed** | Permanent | Permanent | Permanent (rarely reopens) |
| **inactive** | Permanent | Indefinite | Until resumed/completed |
| **booking_expired** | Permanent (dead) | Dead state | Requires manual recovery |

### Maximum Realistic Timelines

**From Intake to First Active Session:**
- **Fast:** 3-5 days (urgent/crisis case)
- **Standard:** 1-2 weeks (typical clinic workflow)
- **Slow:** 2-8 weeks (high demand, low therapist availability)

**Client in ACTIVE State:**
- **Brief:** 1-2 sessions (crisis debriefing, single-issue)
- **Standard:** 8-12 sessions (6-10 weeks at weekly frequency)
- **Long-term:** 6+ months to 1+ year (ongoing therapy)
- **Open-ended:** Indefinite (ongoing relationship)

## Data Fields by State

### Fields Set During Transitions

```
INTAKE
├─ created_at: Set at intake form submission
├─ client_since: Set at form submission
├─ status: Set to 'intake'
├─ name, email, phone, DOB: From form
├─ referral_source: From form
├─ notes: From form (intake notes)
└─ All else: NULL or defaults

ASSESSMENT_PENDING
├─ Updated_at: When status changes
├─ therapist_id: May be assigned here
└─ No new fields created

READY_FOR_BOOKING
├─ Updated_at: When status changes
├─ therapist_id: Confirmed assignment
└─ No new fields created

BOOKING_SCHEDULED
├─ bookings table: New record created
│  ├─ booking_status: 'scheduled'
│  ├─ session_date: Confirmed appointment time
│  ├─ session_type: 'single', 'group', 'couple'
│  ├─ room_id: Room assignment
│  └─ created_at: Booking creation time
├─ clients.updated_at: Updated
└─ clients.therapist_id: Confirmed

PAYMENT_PENDING
├─ bookings.payment_status: 'pending'
├─ bookings.payment_deadline: Set
├─ bookings.marked_paid_at: NULL (not yet paid)
└─ No new tables

ACTIVE
├─ session_notes table: Created after session
│  ├─ booking_id: Links to booking
│  ├─ therapist_id: Recording therapist
│  ├─ notes: Clinical notes
│  ├─ session_outcome: Assessment
│  ├─ progress_score: 1-5
│  └─ created_at: Session completion time
├─ payment_records table: Created
│  ├─ booking_id: Payment for which booking
│  ├─ amount_paid: Payment amount
│  ├─ charge_status: 'pending' or 'collected'
│  ├─ payment_date: When payment processed
│  └─ marked_by_user_id: Who recorded
├─ clients table updated:
│  ├─ total_sessions_completed: Incremented
│  ├─ last_session_date: Updated
│  ├─ total_amount_paid: Summed from payment_records
│  └─ updated_at: Current time

COMPLETED
├─ No new tables
├─ session_notes: Final session notes created
├─ clients table updated:
│  ├─ total_sessions_completed: Final count
│  ├─ last_session_date: Final session date
│  ├─ is_recurring: Set to false (no longer recurring)
│  └─ updated_at: Completion time
└─ Status: Set to 'completed'

INACTIVE
├─ No new tables
├─ clients table updated:
│  ├─ updated_at: When moved to inactive
│  └─ notes: May be updated with pause reason
└─ client_status_history: Reason recorded

BOOKING_EXPIRED
├─ bookings table updated:
│  ├─ booking_status: 'cancelled' or 'expired'
│  ├─ cancelled_at: Expiration time
│  └─ cancellation_reason: Why expired
├─ clients table updated:
│  └─ updated_at: Expiration time
└─ No sessions/payments created
```

## Reporting & Filtering by State

### Query Examples

**Get all clients by status:**
```sql
SELECT id, name, email, status, client_since 
FROM clients 
WHERE status = 'active'
ORDER BY client_since DESC;
```

**Count clients in each status:**
```sql
SELECT 
  status,
  COUNT(*) as count
FROM clients
GROUP BY status
ORDER BY count DESC;
```

**Clients waiting longer than 1 week in intake:**
```sql
SELECT id, name, email, client_since
FROM clients
WHERE status = 'intake'
  AND NOW() - client_since > '7 days'::interval
ORDER BY client_since ASC;
```

**Clients with expired bookings:**
```sql
SELECT c.id, c.name, b.session_date
FROM clients c
JOIN bookings b ON c.id = b.client_id
WHERE c.status = 'booking_expired'
  AND b.booking_status IN ('cancelled', 'expired')
ORDER BY b.session_date DESC;
```

**Active clients by therapist:**
```sql
SELECT 
  t.id,
  t.name as therapist_name,
  COUNT(c.id) as active_clients
FROM therapists t
LEFT JOIN clients c ON t.id = c.therapist_id
WHERE c.status = 'active'
GROUP BY t.id, t.name
ORDER BY active_clients DESC;
```

**Revenue by client status:**
```sql
SELECT 
  c.status,
  COUNT(DISTINCT c.id) as client_count,
  SUM(pr.amount_paid) as total_revenue
FROM clients c
LEFT JOIN payment_records pr ON c.id = pr.client_id
GROUP BY c.status
ORDER BY total_revenue DESC;
```
